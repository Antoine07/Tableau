Atelier · Après les bases SQL / 01

Mission : découvrir Superstore

Situation

Vous rejoignez l’équipe BI d’un hypermarché. Avant de construire un tableau de bord, vous devez comprendre les tables, leurs relations et les principaux indicateurs.

Ce TP prolonge la prise en main de Tableau et le chapitre SQL. Aucune visualisation préconstruite n’est nécessaire : vous construirez les premières vues vous-même.

Télécharger Superstore (.xls)

Livrable : un classeur avec deux feuilles (catégories et régions), une capture des relations et une courte interprétation.

Atelier · Après les bases SQL / 02

Ouvrir le fichier Excel

  1. Dans Tableau Desktop, sélectionnez Microsoft Excel dans Connexion.
  2. Ouvrez sample_-_superstore.xls téléchargé depuis le cours.
  3. Repérez les onglets Orders, Returns et People (selon la version du jeu de données).
  4. Déposez Orders sur le canevas logique ; inspectez les colonnes, les dates et les types.

Questions : quelle table décrit les ventes ? Le nombre de lignes correspond-il au nombre de commandes uniques ? Quel champ identifie un client ?

Atelier · Après les bases SQL / 03

Relier les tables

  1. Glissez Returns à côté de Orders, sans la déposer à l’intérieur du rectangle Orders : choisissez une relation logique.
  2. Vérifiez la correspondance Orders.Order ID = Returns.Order ID.
  3. Ajoutez People et contrôlez la relation Orders.Region = People.Region.
  4. Revenez à l’aperçu : vérifiez les champs et contrôlez que les ventes restent cohérentes.
Orders (lignes de vente)
  ├─[Order ID]── Returns (retours de commande)
  └─[Region]──── People (responsable de région)

Question : qu’arriverait-il à une analyse si une relation créait des doublons ? Une relation logique n’est pas nécessairement une jointure physique.

Atelier · Après les bases SQL / 04

Première vue : ventes par catégorie

  1. Ouvrez une nouvelle feuille puis renommez-la « Catégories ».
  2. Déposez Category sur Lignes.
  3. Déposez Sales sur Colonnes et vérifiez SUM(Sales).
  4. Triez les barres par chiffre d’affaires décroissant.
  5. Placez Profit sur Étiquette ou Info-bulle et comparez les deux mesures.

Questions : quelle catégorie vend le plus ? Réalise-t-elle aussi le plus de bénéfices ? Les chiffres varient selon l’édition du fichier : ne retenez pas de total universel.

Atelier · Après les bases SQL / 05

Deuxième vue : ventes par région

  1. Dupliquez « Catégories » et renommez la copie « Régions ».
  2. Remplacez Category par Region.
  3. Gardez SUM(Sales) et comparez avec SUM(Profit).
  4. Ajoutez éventuellement Category à Filtres pour contrôler le périmètre.

Questions : une région avec de fortes ventes peut-elle dégager un faible bénéfice ? Le filtrage change-t-il la question posée ?

Atelier · Après les bases SQL / 06

Interpréter et restituer

  1. Nommez les trois tables et les deux clés de relation.
  2. Expliquez pourquoi les lignes de vente ne sont pas nécessairement des commandes distinctes.
  3. Indiquez la catégorie et la région en tête de vos ventes, sans confondre avec le bénéfice.
  4. Proposez une question à approfondir, par exemple sur les retours de commande.

À rendre : le classeur de travail, une capture du modèle de relations et cinq lignes de conclusion. À retenir : source → relation → mesure → visualisation → décision.
