01 · Comprendre

Que fait Tableau avec les données ?

Dans Tableau, l'étudiant glisse un champ dans une vue ; Tableau calcule les regroupements et interroge la source de données. Sur une base SQL, Tableau peut générer des requêtes SQL. Sur Excel, l'étudiant utilise les mêmes concepts, mais ne saisit pas de requête SQL personnalisée.

Question métier

Quelles catégories génèrent le plus de ventes ? Est-ce également celles qui dégagent le plus de bénéfice ? Quels retours sont associés aux commandes ?

Matériel : Sample Superstore (.xls). Aucun serveur SQL à installer pour les premières manipulations.

02 · Observer Tableau

La page « Source de données »

  1. Dans Tableau Desktop, choisissez Microsoft Excel puis sample_-_superstore.xls.
  2. Dans la liste des feuilles, identifiez Orders, Returns et People.
  3. Glissez Orders au centre et observez l'aperçu des lignes et les types de champs.

À comprendre : une ligne de Orders correspond généralement à une ligne de commande, pas nécessairement à une commande unique.

04 · Faire le lien avec SQL

SELECT, WHERE et ORDER BY… sans taper de SQL

Dans TableauConcept SQL analogue
Choisir Category et SalesSELECT
Filtrer la régionWHERE
Trier les ventes décroissantesORDER BY
-- Requête pédagogique équivalente (pas à coller dans Excel)
SELECT "Category", "Sales"
FROM Orders
WHERE "Region" = 'West'
ORDER BY "Sales" DESC;
  1. Ouvrez Feuille 1. Glissez Category sur Lignes et Sales sur Colonnes.
  2. Glissez Region sur Filtres et sélectionnez une région.
  3. Triez les barres en ordre décroissant.

Nuance : ce SQL est une analogie pédagogique. La requête effectivement produite par Tableau peut différer, notamment parce que la vue agrège les mesures.

05 · Agréger

SUM, GROUP BY et COUNT DISTINCT

Lorsque vous placez Category et SUM(Sales) dans la feuille, Tableau regroupe les ventes par catégorie.

-- Traduction logique de l'analyse
SELECT "Category", SUM("Sales") AS total_ventes,
       SUM("Profit") AS total_benefice
FROM Orders
GROUP BY "Category";
  1. Dans la même feuille, comparez SUM(Sales) et SUM(Profit).
  2. Créez une seconde feuille par région.
  3. Pour compter les clients uniques, utilisez COUNTD(Customer ID) dans Tableau : cela correspond à COUNT(DISTINCT ...) en SQL.

À retenir : ventes élevées ≠ bénéfice élevé. Et COUNT(*) ne compte pas les clients distincts.

06 · Comparer

Relation Tableau ou JOIN SQL ?

Une relation associe des tables au niveau logique. Une jointure s'effectue dans la couche physique (double-clic sur une table logique) et combine les lignes selon un type de jointure et une clé.

-- Exemple théorique d'une jointure sur Order ID
SELECT o."Order ID", o."Sales", r."Returned"
FROM Orders o
LEFT JOIN Returns r
  ON o."Order ID" = r."Order ID";

Risque : si la table de droite contient plusieurs correspondances pour une clé, une jointure physique peut multiplier les lignes et fausser des totaux.

07 · Comprendre les limites

Où écrire du SQL personnalisé dans Tableau ?

Avec une base de données compatible (par exemple PostgreSQL), Tableau Desktop peut afficher l'option Nouvelle requête SQL personnalisée / New Custom SQL dans la page Source de données.

Important : cette fonction n'est pas disponible sur une connexion Excel moderne. Ne cherchez donc pas ce bouton dans votre fichier Superstore .xls. Pour une vraie manipulation de SQL personnalisé, il faut une base SQL compatible.

Démonstration facultative du formateur

Si une base SQL est disponible, ouvrez une connexion PostgreSQL, choisissez Nouvelle requête SQL personnalisée et saisissez une requête SELECT simple. Sinon, analysez la capture et poursuivez sans blocage.

  2. créer les relations Orders–Returns (Order ID) et Orders–People (Region).
  3. visualiser SUM(Sales) par Category puis filtrer une Region.
  4. ajouter SUM(Profit) ; expliquer les différences entre chiffre d'affaires et bénéfice.
  5. reconnaître dans une requête affichée les rôles de SELECT, WHERE, GROUP BY et JOIN.

Livrables : une capture du modèle de relations, deux graphiques et quatre lignes d'interprétation. Aucune installation de base SQL n'est requise.
